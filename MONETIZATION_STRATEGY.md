# Free / Pro: стратегія

Дата: 2026-10-08. Напрям погоджено; ціна, provider, trial і кінцевий paid scope ще не затверджені.
**Монетизацію враховуємо в дизайні й contracts зараз, продажі не вмикаємо до доказів готовності.**
Початкова beta може бути повністю Free. Попереднє MVP not-now для live subscriptions залишається чинним.

## Обіцянка

Free виконує весь базовий цикл: план -> зрозуміла дія -> запис -> власна історія -> наступний крок.
Pro економить додаткові зусилля або дає регулярний глибший аналіз. Не продаємо безпеку,
повернення власних записів, відсутність штучних перешкод або лише слово AI.

Один Pro, monthly/yearly з однаковими правами. Без трьох складних tier, реклами між підходами,
платного XP, платного порятунку streak, fake countdown і примусового trial перед першим тренуванням.

## Відповідність функціям

F-ID визначені в [feature value](docs/product-review/2026-10-08/03-FEATURE-VALUE.md).
Це pricing intent, не ознака, що всі функції вже реалізовані або залишаються в MVP.

| Рішення | F-ID / межа |
| --- | --- |
| Free core | F01-F22: базовий setup/план/Today, сигнали, logging, edit, каталог, базовий цикл/Calendar |
| Free truth | F24-F27: recovery пояснення, вся власна історія, базові charts, короткий weekly summary, optional weight |
| Free optional layer | F28-F34, F40: лише погоджені корисні налаштування/звички/прогрес, без pay-to-win |
| Free trust | F41, F44, F47-F50, F53: local brief, validation, backup, offline, day sync, доступна shared UI |
| Simplify / не перетворювати на paywall | F35-F39, F45-F46, F52: спершу рішення про користь і зрозумілість |
| Later, не обіцяти в store | F23, F42-F43, F51: advanced annual tools, remote AI/chat, nutrition; окремий доказ потреби |
| Pro candidate, не забирає Free | Нові глибші порівняння періодів і пояснені тренди понад F25/F26; планування/автоматизація понад базовий F20 |
| Поза першим Pro | Cloud sync, unlimited AI, social; не будувати backend для всього застосунку лише заради підписки |

R01 уточнює продуктовий scope; R17 перевіряє готовність платити; R18 реалізує **одну** погоджену
регулярну цінність, а не всі кандидати. Уже збережені плани/історія доступні після expiry;
policy створення/редагування advanced artifacts затверджується окремо без видалення даних.

## Перевірка до продажів

- 8-12 beta учасників як якісна дослідницька пропозиція, не статистично репрезентативний прогноз.
- Спочатку досвід Free; потім показати конкретну корисну Pro-дію, ціну як гіпотезу й альтернативу без покупки.
- Фіксувати проблему, частоту, альтернативний інструмент, причини згоди/відмови. Декларація інтересу не є оплатою.
- Якщо recurring value не підтверджена, відкласти subscription. Разова косметика не достатня причина щомісячної оплати.
- Рахувати сценарії: payers * net revenue per payer - AI/server/provider/support витрати. Ціну/податки/комісії брати з актуальних умов, не обіцяти місячний дохід.

## Правила продукту

Контекстний paywall лише при запиті реальної Pro-можливості, не під час finish/save/restore.
Показувати повну суму і період списання, умови trial/renewal, керування підпискою та зрозумілий Free-вихід.
Ціни надходять зі store, не hardcode гривні. Developer/demo unlock відсутній у production.
Технічна lifecycle policy: [SUBSCRIPTION_RULES](SUBSCRIPTION_RULES.md).

Орієнтир для recurring value і прозорості, перевірено 2026-10-08:
[Google Play subscriptions policy](https://support.google.com/googleplay/android-developer/answer/9900533?hl=en).
Це інженерна стратегія, не юридичне погодження тарифів або регіональних винятків.
