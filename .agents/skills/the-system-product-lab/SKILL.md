# Product lab

## Load context selectively

Follow repository AGENTS.md and [CONTEXT_ROUTER](../../../docs/agent-workflow/CONTEXT_ROUTER.md).
For a broad review start with the product-review index and relevant feature-value
rows. For one idea, read only its matching sections. Treat old RPG positioning as
historical where it conflicts with the owner's broad-audience clarification.
Use GRAPH_REPORT and a targeted code read to verify feasibility, not a full scan.

## Explore and narrow

1. State the user's intended outcome and distinguish confirmed constraints from assumptions. Ask only questions that change the decision; reuse answers already documented.
2. Map the user's task, current friction and real benefit before proposing a feature. Training is the strongest current implementation, not permission to silently discard the broader personal-system ambition.
3. Offer a small set of distinct alternatives, including simplification or no new feature. Creativity may come from clearer decisions, forgiving return paths, meaningful milestones or faster interaction, not extra screens.
4. For each candidate give: user value, fit with core loop, novelty claim/confidence, effort/dependencies, risk, what it replaces, smallest useful experiment and a stop criterion.
5. Recommend keep / improve / defer / consider removing. Removal is a proposal, never authorization to delete code, actions or data.

## Creative guardrails

- Make the personal-system idea understandable without anime knowledge. Use original language/assets, not copied characters, names or artwork.
- Reward understandable real progress. Do not present fictional stats as measured fitness, health or intelligence.
- Explore optional, restrained progression and supportive return-after-a-break paths; do not prescribe exercise to compensate for missed days or design shame/compulsion loops.
- A short-action option must respect existing recovery/rest decisions and user choice, not override safety logic to protect a streak.
- Sharing is opt-in with private fitness/health details excluded by default. No dark patterns, forced invites or manufactured urgency.
- Claims about competitors or current standards need fresh primary sources. Separate inspiration from originality claims; no promise of virality, retention or revenue.
- Synthetic personas and AI brainstorming do not count as real user research. Propose small tests with people before broad investment.

## Deliverable and stop

Return a prioritized recommendation, alternatives/trade-offs, evidence pointers
and open decisions in the user's language. Keep facts, inferences and hypotheses
distinct. Use [TEAM_REVIEW](../../../docs/agent-workflow/TEAM_REVIEW.md) only for a
requested independent team review; do not simulate consensus.

In planning mode stop for discussion before architecture or implementation.
For an explicitly approved implementation task, preserve its scope and hand off
the agreed requirements without restarting a full product audit.
