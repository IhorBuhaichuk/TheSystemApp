## Головна відповідь

**Залишити Kotlin + Jetpack Compose + Room + Hilt.** Для Android-first застосунку з локальною історією тренувань, Health Connect і власною HUD-системою це доцільний стек. Переписування на знайому з Full Stack курсу мову не має доведеної переваги для цього проєкту. Сучасні рекомендації Android підтримують Compose, ViewModel, repositories, Flow і dependency injection. [Android architecture](https://developer.android.com/topic/architecture/recommendations).

**Найбільший резерв якості зараз у завершеності продукту, а не в іншій мові.** Треба замкнути шлях «початкове налаштування -> конкретний план -> виконання -> надійний запис -> зрозумілий результат -> наступна дія». Власний стиль уже є; довіру й зручність ще потрібно довести.

Моє формулювання суті:

> THE SYSTEM допомагає людині рухатися до власних цілей: перетворює план на зрозумілі щоденні дії, зберігає виконане й показує реальний розвиток. У поточній реалізації найглибше опрацьоване ядро тренувань, навколо якого є допоміжні звички та завдання.

Не «гра замість тренувань», не медичний оцінювач і не чат із ШІ, навколо якого побудовано журнал.

**Уточнення власника під час аналізу:** Solo Leveling є натхненням для принципу персональної системи, а не вимогою знати аніме. Продукт має бути зрозумілим широкій аудиторії, із ненав'язливою гейміфікацією. Це уточнює попереднє anime/RPG-позиціонування в старих документах. Сьогодні ті документи й UI не переписуються; нова рекомендація зафіксована тут і в розділі 04.

## П'ять найбільш цінних рішень

1. Залишити нативний Android; оновлювати конкретні залежності за потребою, не починати повне переписування.
2. Довести до кінця перше тренування, збереження чернетки, одноразове завершення та відновлення даних.
3. Показувати, що система знає, чого не знає і чому пропонує саме цю дію.
4. Залишити необов'язковий компактний шар гейміфікації; звичайна мова й реальний результат мають бути зрозумілі без аніме-контексту.
5. Перевірити користь на невеликій beta: чи люди самостійно починають, завершують і повертаються після пропуску.
